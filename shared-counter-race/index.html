Challenge 1

Predict first: put Redis ten times closer (RTT_MS = 0.05). Does a faster network fix the race?

Show the answer

No: 51,719 get through, still 26 times the limit. A shorter trip means fewer requests overlap (25 per round trip instead of 250), but every overlap still loses an update. Speed shrinks the race; only an atomic step (INCR, or a Lua script) removes it. With ATOMIC = True it's exactly 2,000 at any distance.

Challenge 2

Calm the traffic down: RATE = 2_500, only 25% over the limit. Surely the race only matters in a storm?

Show the answer

2,487 of 2,500 get through: the limiter barely limits at all. That's about one request per round trip, so a GET often reads the counter before the last SET lands, and the stale value + 1 overwrites newer counts. The counter keeps falling behind and rarely reaches 2,000. A race needs only two requests in flight, not a storm.
